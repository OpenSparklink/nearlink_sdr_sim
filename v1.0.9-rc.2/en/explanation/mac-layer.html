MAC Layer Details¶

This document explains the design and implementation of the SparkLink SLE data link layer (MAC layer), covering broadcast and discovery, access procedures, link management state machines, frame structure and signaling codec, QoS management, and timing scheduling, cross-referenced against Chapter 7 of TXS-10002-2025.

Broadcast and Discovery (§7.1.1-7.1.2)¶

Broadcasting is the starting point for SLE communication. The G node periodically transmits broadcast frames; T nodes scan these frames to discover nearby devices.

Two-Level Broadcast Frame Structure¶

SLE broadcast frames have two levels:

  • Basic broadcast frame: uses FT1 or FT4 frame type, transmitted 3 times sequentially on 1 to 3 broadcast channels

  • Extended broadcast frame: sent immediately after the basic broadcast frame with a minimum gap of 300 \(\mu\)s, carrying additional information

The basic broadcast frame provides the minimum information required for device discovery; the extended broadcast frame indicates access resources, transmission parameters, System Management Frame configuration, and other details.

Broadcast Frame Data Types¶

A broadcast frame consists of multiple sub-info entries, each containing a type index and payload. The standard defines 11 data types:

Implementation: The mac.broadcast module defines the BroadcastDataType enum and 21 sub-information data classes, including ExtAdvResourceConfig, DiscoveryAccessResourceConfig, AccessBasicInfo, etc.; each class implements pack()/unpack(). BroadcastFrame encapsulates the overall broadcast frame encoding/decoding.

Discovery Procedure (§7.1.2)¶

Discovering devices (T nodes) listen to basic and extended broadcast frames to extract device information. Optional active query procedure:

  1. T node sends query request frame (with filter information)

  2. G node replies with query response frame

Code implementation: mac.access.DiscoveryManager manages the discovery procedure and maintains the discovered device list.

Broadcast Frame Filtering (§7.1.5)¶

The receiver can configure filtering rules to accept only broadcast frames meeting certain conditions, supporting filtering by address, access type, etc.

Implementation: mac.broadcast.BroadcastFilter, using FilterCondition and FilterOp to define rules.

Access Procedure (§7.1.3)¶

Access is the process by which a T node establishes a connection with a G node, and proceeds in the following steps:

        sequenceDiagram
    participant G as G节点
    participant T as T节点
    G->>T: 发送可接入扩展广播帧
    T->>G: 接入请求帧 (GT偏好)
    G->>T: 接入响应帧 (结果+角色)
    Note over G,T: 协商G/T角色完成
    Note over G,T: 分配首次调度点
    Note over G,T: 建立异步数据链路
    Note over G,T: 配对和鉴权管理 或 安全保护
    Note over G,T: 加密数据传输开始

The access request carries GT role preferences; the G node decides whether to accept and determines the final role assignment based on its own policy.

Role Negotiation¶

GT role negotiation has four outcomes:

  • Negotiate T node: accept request, initiator becomes T

  • Negotiate G node: accept request, initiator becomes G

  • Fixed T node: forcibly assigned as T

  • Fixed G node: forcibly assigned as G

Access Whitelist (§7.1.6)¶

The G node can configure an address whitelist to allow only known devices to access. The whitelist is based on address matching and supports dynamic add/remove.

Code implementation: the mac.access module provides two managers:

  • BroadcasterAccessManager: G node side, sends broadcasts, handles requests, sends responses

  • InitiatorAccessManager: T node side, sends requests, handles responses

  • AccessWhitelist: address whitelist

  • AccessPhase enum: IDLE → ADV_SENDING → REQ_WINDOW → RSP_WINDOW → LINK_SETUP → COMPLETED

Key timing constraints: the interval from broadcast frame to extended broadcast frame must be at least 300 \(\mu\)s; the interval from extended broadcast frame to access request must be at least 300 \(\mu\)s.

Link Management State Machine (§7.1/7.2)¶

The link manager (LinkManager) is the core component of the MAC layer, managing the complete link lifecycle through an event-driven finite state machine.

State Definitions¶

        stateDiagram-v2
    IDLE --> BROADCASTING
    IDLE --> SCANNING
    BROADCASTING --> CONNECTED
    SCANNING --> ACCESSING
    ACCESSING --> CONNECTED
    ACCESSING --> PAIRING
    PAIRING --> CONNECTED
    CONNECTED --> DISCONNECTED
    CONNECTED --> DORMANT
    DORMANT --> CONNECTED

8 states:

State

Meaning

IDLE

Idle, not participating in any communication

BROADCASTING

G node is transmitting broadcast frames

SCANNING

T node is scanning for broadcasts

ACCESSING

Executing access procedure

CONNECTED

Link established, can transmit/receive data

PAIRING

Executing security pairing

DORMANT

Sleep state (§7.2.14)

DISCONNECTED

Link disconnected

Event Types¶

The state machine processes 21 event types driving state transitions, in these main categories:

  • Broadcast/discovery: start/stop broadcast and scan, receive broadcast frames

  • Access: send/receive requests and responses

  • Signaling: send/receive link control signaling

  • Pairing: initiate pairing, completion, failure

  • Disconnect: active disconnect request, peer disconnect, supervision timeout

  • Sleep: sleep request, wake request, wake reception

Link Parameters¶

LinkParams stores the current link operating parameters:

  • transceive interval (interval_us)

  • Maximum data length (max_data_length)

  • Hopping table (hop_table)

  • Frame type (frame_type)

  • CRC length (crc_len)

  • Supervision timeout (supervision_timeout_ms)

These parameters can be dynamically updated via control plane procedures (§7.2.1-7.2.25).

Implementation: The mac.link_manager.LinkManager class drives state transitions via process_event(Event) and notifies the upper layer through the LinkManagerCallback interface.

Control Plane Procedures (§7.2)¶

The standard defines 25 control plane procedures, all supporting bidirectional initiation by G and T nodes:

Link Parameter Update (§7.2.1-7.2.2)¶

  • transceive interval update: request → accept/reject or direct update

  • Multi-level transceive interval: supports switching interval parameters between different priorities

Link Capability Negotiation (§7.2.4-7.2.6)¶

  • Feature exchange: exchange capability feature bitmaps supported by both sides

  • Version exchange: exchange protocol version information

  • Data length update: negotiate maximum PDU length

Channel Management (§7.2.7-7.2.12)¶

  • Channel quality reporting: configure channel quality reporting period and method

  • Hopping table update: update frequency hopping sequence

  • Hopping map update: update channel availability bitmap

  • Minimum available channels: ensure available channel count does not fall below threshold

  • CRC switching: switch between CRC24 and CRC32

  • Physical layer update: switch frame type or modulation parameters

Connection Management (§7.2.13-7.2.17)¶

  • Power control: request → response → adjust transmit power (§7.2.13)

  • Sleep and wake: one side requests sleep, other confirms; reverse for wake (§7.2.14)

  • Role switching: G/T role swap (§7.2.15)

  • PING procedure: detect link connectivity (§7.2.16)

  • Link disconnect: send disconnect indication, release resources (§7.2.17)

Advanced Link Management (§7.2.18-7.2.25)¶

  • Connected asynchronous link: parameter reconfiguration/update/setup/teardown (§7.2.18)

  • Synchronous isochronous link: setup/parameter exchange/parameter update (§7.2.19)

  • Broadcast link: establishment/parameter update/hopping map/disconnect (§7.2.20)

  • System management frame link: parameters/time slot update/channel status (§7.2.21)

  • Asynchronous multicast link: establishment/parameters/disconnect/timeout (§7.2.22)

  • Narrowband/UWB measurement and sensing: measurement and sensing procedure management (§7.2.23-7.2.25)

Implementation: mac.link_manager.LinkManager provides handling logic for all 25 procedures internally, driven by 109 signaling types from mac.link_control. mac.power_control independently implements 3 power control signaling types.

Frame Structure (§7.3)¶

MAC frames are divided into three types:

Control Plane Frame (§7.3.2)¶

┌────────────────┬────────────┬──────────┐
│ 数据类型索引   │ 数据长度   │  载荷    │
│   2 字节       │  1 字节    │  N 字节  │
└────────────────┴────────────┴──────────┘

The data type index identifies the signaling type (130 types); data length indicates the payload byte count.

Data Plane Frame (§7.3.3)¶

Asynchronous data frame (§7.3.3.2):

┌────────────┬─────────────┬──────────┬──────────┐
│ 分段标志   │ 数据长度    │  保留    │  数据    │
│  2 bit     │  11 bit     │  3 bit   │  N 字节  │
└────────────┴─────────────┴──────────┴──────────┘

Segmentation flag (SegmentType): COMPLETE / FIRST / MIDDLE / LAST, supporting large PDU segmented transmission.

Synchronous data frame (§7.3.3.3): adds PDU sequence number, event group number, and time offset fields, suitable for isochronous transmission.

Multiplex Frame (§7.3.4)¶

Multiplex frames allow control plane data and user plane data to be carried simultaneously in a single physical frame:

┌──────────────────────┬────────────────┐
│  控制面帧列表        │  可选数据帧    │
│  (多个控制帧级联)    │  (异步/同步)   │
└──────────────────────┴────────────────┘

Implementation: The mac.frame module defines ControlFrame, AsyncDataFrame, SyncDataFrame, MuxFrame, each with pack()/unpack() methods.

Each signaling type is a data class containing DATA_TYPE_INDEX, BYTE_LENGTH, field definitions, and pack()/unpack() methods.

The signaling registry (mac.signaling) maintains an index-to-class mapping, providing a unified encode/decode interface:

  • encode_signaling(msg) → serialize to ControlFrame

  • decode_signaling(frame) → parse a specific signaling object from ControlFrame

QoS Management (§6.5)¶

The QoS manager ensures data transmission reliability and efficiency:

ARQ Automatic Retransmission¶

Sequence number management and retransmission control. Different frame types have different moduli:

Frame Type

SN Modulus

FT1

2

FT2

2

FT3/FT4

32

HARQ Hybrid Retransmission¶

Supports two feedback modes:

  • TB (transport block): ACK/NACK for the entire transport block

  • CBG (code block group): feedback at code block group granularity, partial retransmission (up to 8 CBGs)

Flow Control¶

Credit-based transmit window control, preventing the sender from overwhelming the receiver.

Link Quality Tracking¶

Real-time frame error rate (FER) statistics, computing recommended MCS index, supporting adaptive modulation and coding (AMC).

Priority Queue¶

Five priority levels: CONTROL > REALTIME > HIGH > NORMAL > LOW; higher priority payloads are sent first.

Implementation: mac.qos.QosManager integrates ArqState, HarqController, FlowController, LinkQualityTracker, and TxQueue.

Timing Scheduling (§6.3/6.6)¶

Superframe Structure¶

SLE timing is organized by superframes (Superframe); the period between two system management frames (SMF) constitutes one superframe cycle. Each superframe is subdivided into multiple time slices (TimeSlice), each assigned to a specific link.

System Management Frame (§6.6)¶

SMF is the scheduling information frame broadcast by the G node to all T nodes, containing:

  • Scheduling signaling: time slot allocation and link scheduling

  • Link signaling: link parameter update notification

  • Offset signaling: time offset correction

SMF transmission scheduling is managed by mac.smf_scheduler.SMFTransmitScheduler.

Event Groups (§Appendix D)¶

Event groups combine multiple transmission events into a group for synchronous scheduling in isochronous scenarios.

Implementation: mac.scheduler.ScheduleManager manages superframes, event groups, and multi-level transceive intervals; mac.smf handles SMF frame encoding/decoding; mac.smf_scheduler manages transmission scheduling.

Non-Connected State Broadcast (§7.1.7)¶

Devices can broadcast data without establishing a connection, suitable for periodic announcement scenarios. Non-connected state broadcast frames use independent parameter configurations and do not interfere with connected data transmission.

Implementation: mac.access.NonConnectedBroadcastManager, used together with NonConnectedBroadcastConfig.
