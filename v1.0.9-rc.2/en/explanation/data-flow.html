End-to-End Data Flow¶

Starting from application data, this article traces the complete processing pipeline of a data packet from the transmitter to the receiver, covering MAC-layer encapsulation, channel coding, modulation and pulse shaping, over-the-air transmission, reception and demodulation, and data recovery.

Transmit Pipeline¶

Step 1: QoS Decision¶

SleNode.transmit() first calls QosManager.prepare_tx(), which fetches data to send from the priority queue:

  • Five-level priority queue: CONTROL > REALTIME > HIGH > NORMAL > LOW

  • Flow control check: whether the transmit window has credit

  • HARQ check: whether there are code blocks requiring retransmission

Step 2: Frame Encryption (optional)¶

If encryption is enabled on the link, call FrameCryptoContext.encrypt():

  1. Compute IV: compute_iv(iv_base, sync_or_link_id, frame_type)

  2. Build CCM nonce: build_ccm_nonce_async(flag, payload_count, direction, iv, data_len), taking B0[1:14] as the 13-byte nonce

  3. AES-CCM encryption: aes_ccm_encrypt(session_key, nonce, plaintext, aad, mic_len) → ciphertext + MIC

  4. payload_count incremented

Step 3: MAC Frame Encapsulation¶

Data is encapsulated into an AsyncDataFrame:

┌────────────┬─────────────┬──────────┬──────────┐
│ 分段标志   │ 数据长度    │  保留    │  载荷    │
│  2 bit     │  11 bit     │  3 bit   │  N 字节  │
└────────────┴─────────────┴──────────┴──────────┘

If data exceeds the maximum PDU length, it is segmented as FIRST / MIDDLE / LAST.

Step 4: Channel Coding (tx_chain)¶

mac_to_iq() converts MAC bytes to a bit stream, builds control information, then calls tx_chain():

Header Coding (encode_head)¶

Control information bits (28 or 44 bits) undergo:

  1. Polar coding: select information bit positions per the reliability sequence, freeze bits set to zero, butterfly operations generate codewords

  2. Scrambling: 7-bit Galois LFSR (\(x^7 + x^4 + 1\)), XOR each bit

Payload Coding (encode_payload)¶

User data bits undergo:

  1. CRC attachment: compute CRC-24 or CRC-32, append to data tail

  2. Code block segmentation: when the encoded bit count exceeds the maximum Polar mother code length, split data into multiple code blocks

  3. Polar coding: each code block is independently Polar-coded at the rate specified by MCS

  4. Scrambling: using the same LFSR as the header, XOR each codeword bit

Step 5: Frame Assembly¶

The encoded bits are assembled according to the frame structure:

┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 前导码   │ 同步序列 │ 头部     │ 载荷     │ (导频)   │
│ m序列    │ SyncWord │ Polar码字│ Polar码字│ 定期插入 │
└──────────┴──────────┴──────────┴──────────┴──────────┘

  • Preamble: m-sequence; different frame types use different lengths (FT1: 32 bit, FT2: 64 sym, FT3: 62 sym, FT4: 126 sym)

  • Sync sequence: generated from PID, used for frame synchronization detection

  • Pilots: known symbols periodically inserted at pilot_interval intervals for channel estimation

Step 6: Modulation Shaping¶

  • FT1 (GFSK): Gaussian frequency shift keying, BT = 0.5, directly modulated as instantaneous frequency deviation

  • FT2-FT4 (PSK): phase-shift keying (BPSK/QPSK/8PSK) — first map to constellation points, then apply RRC pulse-shaping filter (roll-off factor \(\beta = 0.4\))

Output is a complex baseband IQ signal.

Step 7: RF Transmission¶

  • Simulation mode: IQ fed directly into the channel model

  • USRP mode: IQ sent via SLETransceiver to USRP E310 hardware, up-converted to the 2.4 GHz band

Over-the-Air Transmission¶

Channel Effects¶

Data traversing the wireless channel is subject to:

  • Multipath fading: Rayleigh/Rician fading, multipath delay spread

  • Frequency offset: carrier frequency offset caused by local oscillator mismatch

  • Doppler spread: time-varying channel caused by relative motion

  • Noise: additive white Gaussian noise (AWGN)

  • Multi-user interference: co-frequency signal interference from other devices

Frequency Hopping¶

Both transmitter and receiver switch channels in the 2402-2480 MHz band according to the same hopping sequence, jumping to a different frequency point each slot to improve frequency diversity gain and reduce narrowband interference.

Receive Pipeline¶

Step 1: RF Reception¶

  • USRP mode: hardware down-conversion, ADC sampling yields baseband IQ

  • Simulation mode: IQ signal obtained from channel model output

Step 2: Matched Filtering¶

  • FT1 (GFSK): GFSK demodulator directly extracts instantaneous frequency

  • FT2-FT4 (PSK): RRC matched filtering to maximize SNR, then downsample to 1 sample/symbol

Step 3: Frame Synchronization (frame_sync)¶

Sliding cross-correlation detects the sync sequence:

  1. Generate sync reference sequence based on frame type

  2. Compute cross-correlation between received signal and reference sequence

  3. When peak exceeds twice the mean, synchronization is declared successful; return frame start position

Step 4: Frame Structure Parsing¶

symbols_to_data_bits() splits the segments according to frame configuration parameters:

  1. Skip preamble and sync sequence

  2. Extract header symbols (fixed length)

  3. Extract payload symbols (length indicated by header or known in advance)

  4. Remove pilot symbols

Step 5: Header Decoding (decode_head)¶

  1. Descrambling: same LFSR XOR to recover the original codeword

  2. Polar decoding: SC (successive cancellation) decoding, recover control information bits

  3. CRC-12 check: verify header integrity

Step 6: Payload Decoding (decode_payload)¶

  1. Descrambling: LFSR XOR

  2. Polar decoding: each code block decoded independently

  3. Code block reassembly: multiple code blocks merged into complete data

  4. CRC check: CRC-24 or CRC-32 verifies data integrity

Step 7: MAC Frame Decapsulation¶

  1. Bit stream converted to bytes: bits_to_bytes()

  2. Parse AsyncDataFrame: extract segmentation flags and payload

  3. Segment reassembly: if segmented, concatenate by sequence number

Step 8: Frame Decryption (optional)¶

Call FrameCryptoContext.decrypt():

  1. Build nonce with the same parameters as the transmitter

  2. AES-CCM decrypt and verify MIC

  3. payload_count incremented

  4. Discard if MIC verification fails

Step 9: QoS Feedback¶

  • ARQ: send ACK/NACK

  • HARQ: feedback TB or CBG granularity acknowledgement

  • Flow control: update credit

  • Quality tracking: update frame error rate statistics, recommend MCS

SleNode Integration¶

SleNode is the node class integrating all functionality into a single entity:

SleNode
├── TxConfig          发射配置
├── QosManager        QoS 管理 (ARQ/HARQ/流控)
├── LinkManager       链路状态机 (8 状态)
├── FreqTable         跳频表
├── PowerController   功率控制
├── ScheduleManager   时序调度
├── FrameCryptoContext 帧加密上下文
├── ChannelModel      仿真信道 (可选)
└── SLETransceiver    USRP 收发器 (可选)

Data flow paths:

  • Transmit: send(data) → enqueue → transmit() → QoS → encrypt → MAC → PHY → IQ → air

  • Receive: air → IQ → receive() → PHY → MAC → decrypt → QoS feedback → on_data_received()
