Physical Layer Details¶

This document explains the design and implementation of the SparkLink SLE physical layer in detail, covering modulation waveforms, frame structure, channel coding, and TX/RX pipelines, with each section cross-referenced against TXS-10002-2025 clauses and implementation notes.

Modulation Schemes¶

The SLE physical layer supports two main modulation categories: frequency shift keying (GFSK) and phase shift keying (PSK), used for different frame types.

GFSK Modulation (§6.2.1.1)¶

Gaussian frequency shift keying is the only modulation scheme for FT1 frames. The standard specifies:

  • Gaussian filter bandwidth-time product BT = 0.5

  • Modulation index h in the range 0.45 to 0.55, default 0.5

  • Bit 1 corresponds to positive frequency deviation, bit 0 to negative

SLE defines 7 bandwidth configurations, from 0.1 MHz to 4 MHz:

Implementation: phy.gfsk.GFSKModulator class. The modulation chain is: NRZ mapping → upsampling → Gaussian filtering → frequency integration → complex baseband:

\[ s(t) = \exp\!\left(j \cdot 2\pi h \int_0^t \sum_k a_k \cdot g(\tau - kT)\,d\tau\right) \]

Demodulation uses a non-coherent frequency discriminator scheme (GFSKDemodulator), extracting instantaneous frequency from the phase difference between adjacent samples.

PSK Modulation (§6.2.1.2)¶

FT2-FT4 frames use phase shift keying, supporting three modulation orders:

BPSK (1 bit/symbol):

  • Bit 0 → phase 90°, bit 1 → phase -90°

  • Even-position symbols additionally rotated 90° clockwise

QPSK (2 bits/symbol):

  • 00→45°, 01→135°, 11→-135°, 10→-45°

  • Even-position symbols additionally rotated -45°

8PSK (3 bits/symbol):

  • Gray coded, 22.5° spacing

  • Even-position symbols additionally rotated -22.5°

“Even position” definition: the first symbol in the radio frame is at an odd position (index 0 = odd), index 1 = even, and so on. This additional rotation improves clock recovery performance.

Pulse shaping uses a root raised-cosine (RRC) filter with roll-off \(\beta = 0.4\) and 4 samples per symbol by default. An RRC filter at each end of the link satisfies the Nyquist ISI-free criterion when cascaded.

Implementation: phy.psk.PSKModulator class. Constellation mappings are defined in constants BPSK_MAP, QPSK_MAP, _8PSK_MAP, etc. Pilot symbols share the same phase lookup table, generated by the phy.pilot module.

There is also a non-rotated BPSK mapping (0→0°, 1→180°) used for m-sequence modulation in sync signals 3/4, which does not participate in even-position rotation.

Multitone Signal (§6.2.1.3)¶

Multitone signals are formed by superimposing N single tones:

\[ S(t) = \sum_{i=0}^{N-1} A_i \cdot e^{j(\omega_i t + \phi_i)} \]

Primarily used for RF calibration and measurement scenarios. The phy.multitone module implements multitone signal generation with configurable number of tones, amplitudes, and initial phases.

UWB Pulse (§6.2.1.4)¶

UWB pulse signals use a Kaiser-window reference waveform (\(\beta = 10\)), supporting two bandwidths:

Code implementation: phy.uwb_pulse module, provides reference pulse generation, chip modulation, and cross-correlation verification.

Frame Structure (§6.3)¶

Wireless Frame Composition¶

Each physical frame consists of a header and data portion:

┌─────────── 帧头 ───────────┐┌───── 数据 ──────┐
│ 前导码 │ 同步序列 │ 控制信息 │ 载荷数据 │ CRC   │
└───────┴─────────┴─────────┘└─────────┴───────┘

Differences between frame types are mainly in the header’s coding and modulation schemes:

FT1 — Broadcast Frame (§6.3.2)¶

  • Preamble: GFSK, [0,1] alternating, 10 \(\mu\)s

  • Sync sequence: sync_signal_1, 32-bit → 32 GFSK symbols

  • Control info: Group A, no Polar coding, GFSK modulation

  • Payload: no Polar coding, directly GFSK modulated

  • Typical use: broadcast, discovery, access request/response

FT1 is the lightest frame type with no forward error correction coding overhead. The control information header is protected by BCH code; the CRC seed is determined by the lower bits of the sync sequence.

FT2 — Short-Header Data Frame (§6.3.3)¶

  • Preamble: PSK, [\(\pi/4\), 0] alternating, 10 \(\mu\)s

  • Sync sequence: sync_signal_2, 64-bit → 32 QPSK symbols

  • Control info: Group A, Polar(64,K) coded → 32 QPSK symbols, pilot interval 16

  • Payload: code block segmentation (no intra-segment CRC) → Polar coding → PSK modulation + pilots

  • Pilots: optional, interval 4/8/16

FT3 — Long-Header Data Frame (§6.3.4)¶

  • Preamble: PSK, [\(\pi/4\), 0] alternating, 12 \(\mu\)s

  • Sync sequence: sync_signal_3, 31+31 bits → 62 BPSK symbols (based on m31 sequence)

  • Control info: Group B, Polar(256,K) → 128 QPSK symbols, pilot interval 4

  • Payload: code block segmentation (with intra-segment CRC) → Polar coding → PSK modulation + pilots

  • Feature: Group B CRC seed = 0x555555 ^ LLID

FT4 — Extended-Header Data Frame (§6.3.5)¶

  • Preamble: PSK, [\(\pi/4\), 0] alternating, 16 \(\mu\)s

  • Sync sequence: sync_signal_4, 63+63 bits → 126 BPSK symbols (based on m63 sequence)

  • Control info: Group B, Polar(256,K) → 256 BPSK symbols, pilot interval 4

  • Payload: same coding scheme as FT3, but longer sync sequence, suitable for low SNR scenarios

Timing Parameters¶

The system base slot \(T_{sys} = 125\,\mu s\), represented by a 30-bit counter. Scheduling slots have five options: 25/50/75/100/125 \(\mu\)s. The over-the-air frame duration is determined by:

\[ T_{frame} = T_{preamble} + T_{sync} + T_{ctrl} + T_{data} + T_{guard} \]

Implementation: The _SYNC_CONFIG and _CTRL_CONFIG dicts in phy.frame define the complete parameters for all four frame types. assemble_frame_bits() generates the bit-level frame structure; frame_to_symbols() converts it to modulation symbols.

Physical Layer Control Information (§6.4)¶

Control information is the structured field immediately following the sync sequence in the frame header, carrying frame type, payload length, MCS, and other metadata.

Group A (FT1/FT2)¶

Group A control information uses CRC12 verification; the seed comes from the lower 12 bits of the sync sequence. Seven subtypes are defined:

Type

Purpose

A1

Broadcast/discovery/access

A2

Asynchronous data (control plane)

A3

Asynchronous data (data plane)

A4

Asynchronous data (multiplex)

A5

Synchronous isochronous

A6

Semi-reliable multicast feedback

A7

Measurement management

Group B (FT3/FT4)¶

Group B uses CRC24B with a fixed seed 0x555555; the CRC result is XOR-ed with link identifier LLID. Five subtypes are defined (B1-B5) for asynchronous data, synchronous isochronous, and measurement scenarios.

Implementation: The phy.control_info module provides data classes ControlInfoA1 through ControlInfoA7 and ControlInfoB1 through ControlInfoB5, each implementing pack() and unpack() methods.

Pilots (§6.7)¶

Pilot symbols are reference symbols with known phase, periodically inserted into the data symbol stream for channel estimation and phase tracking at the receiver.

Pilot phase is aligned with the standard phase for the modulation order: BPSK 90°, QPSK 45°, 8PSK 22.5°. Even-position pilots undergo the same additional rotation as data symbols.

Insertion rule: 1 pilot inserted after every \(N\) data symbols; \(N\) can be 4/8/16. Pilots at the end of the frame may be omitted.

FT1 does not use pilots. FT2 pilots are optional (default interval 16). FT3/FT4 mandate pilots (default interval 4).

Code implementation: phy.pilot.insert_pilots() and remove_pilots() functions.

Channel Coding (§6.9-6.11)¶

CRC computation supports seed values; Group A seed comes from the sync sequence, Group B seed = 0x555555 ^ LLID.

Code implementation: common.crc.crc_calculate(), with Rust acceleration support (_HAS_RUST_CRC auto-detected).

Polar Coding (§6.10.1)¶

SLE uses Polar codes for forward error correction with the following core parameters:

  • Mother code length \(N\): 32, 64, 128, 256, 512, 1024

  • Information bit count \(K\): determined by MCS index and payload length

  • Reliability sequence: standard Appendix C provides 1024-level fixed ordering

The encoder performs butterfly GF(2) transform; the decoder uses successive cancellation (SC) algorithm with SSC pruning (fast paths for rate-0/rate-1 subtrees).

Implementation: common.polar.PolarEncoder / PolarDecoder, both support Rust acceleration (PyO3 extension nearlink_sdr_accel). Encoding ~10× faster, decoding ~10× faster.

Code Block Segmentation (§6.10.2)¶

When payload exceeds a single Polar code block capacity, code block segmentation is performed:

  • Without intra-segment CRC (FT2): payload evenly divided into multiple code blocks, each independently Polar-coded

  • With intra-segment CRC (FT3/FT4): each code block has an additional CRC appended, enhancing reliability

Implementation: segment_without_crc() and segment_with_crc() functions in the common.code_block_seg module.

BCH Coding (§6.11)¶

FT1 control information header is protected by BCH code:

  • BCH(31,26): corrects 1-bit errors

  • BCH(63,24): corrects more errors, used for longer control fields

Code implementation: common.bch module.

Channel Bit Scrambling (§6.10.4)¶

Scrambling uses a 7-bit Galois LFSR with polynomial \(x^7 + x^4 + 1\) and period 127. The seed (whitening_seed) is indicated in the control information; both TX and RX use the same seed for recovery.

Code implementation: common.scrambler.scramble(), internally pre-computes one period of the scrambling sequence and extends with tile.

Frequency Hopping (§6.10.3, §8.1)¶

The SLE narrowband system uses 79 channels in the 2402-2480 MHz band (1 MHz spacing). The hopping sequence is driven by a pseudo-random number generator, switching channel at each scheduling point.

Key parameters:

  • Hopping seed: 24-bit, determines sequence randomness

  • Hopping map: 79-bit bitmap, marks the availability of each channel

  • Minimum available channels: has a lower threshold to prevent too few available channels

Code implementation: FreqTable in the phy.freq_hopping module, manages the channel list, hopping sequences, and masking operations.

Transmit Pipeline (§6.10)¶

Complete TX processing chain (phy.tx_pipeline.tx_chain):

应用数据
  ↓
CRC 附加                   ← common.crc
  ↓
码块分割                    ← common.code_block_seg
  ↓ (FT2-4)
Polar 编码                  ← common.polar
  ↓
比特加扰                    ← common.scrambler
  ↓
符号映射                    ← phy.psk / phy.gfsk
  ↓ (FT2-4)
导频插入                    ← phy.pilot
  ↓
帧组装                      ← phy.frame
  (前导 + 同步 + 控制信息 + 载荷)
  ↓
脉冲成型                    ← RRC / GFSK 滤波
  ↓
复基带 IQ 信号输出

Transmit parameters are configured via TxConfig, including frame type, MCS index, PID, scrambling seed, CRC length, and pilot interval.

Receive Pipeline (§6.10)¶

The RX processing chain (phy.rx_pipeline.rx_chain) is the reverse of transmission:

复基带 IQ 信号输入
  ↓
匹配滤波                    ← RRC / GFSK 频率鉴别
  ↓
帧同步                      ← 同步序列互相关
  ↓
头部提取与解码
  符号解映射 → 解扰 → Polar 解码 → CRC 校验
  ↓
导频去除                    ← phy.pilot
  ↓
载荷解调与解码
  符号解映射 → 解扰 → Polar 解码 → 码块重组 → CRC 校验
  ↓
数据比特输出 + CRC 状态

Frame synchronization detects the peak position of the sync sequence via sliding cross-correlation; a peak exceeding the threshold indicates a frame is detected.

RF Compliance (§8)¶

The phy.rf_compliance module implements RF parameter verification from standard Chapter 8:

  • Transmitter: output power level, GFSK modulation accuracy (frequency deviation tolerance), PSK modulation accuracy (EVM), GFSK spurious emissions, PSK spectral template

  • Receiver: sensitivity and maximum input level, channel selectivity, spurious emissions, RSSI measurement accuracy

  • UWB: channel parameter compliance, spectral mask, normalized root mean square error

These verification functions return compliant/non-compliant judgments, suitable for automated verification after simulation.
